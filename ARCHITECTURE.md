# Architecture

## Overview

The application is a static, browser-first scoring console. Match state lives in the scorer's browser and is persisted in `localStorage`. Supabase is used only when a scorer creates a second-referee share session.

## Frontend

| Area | Files | Responsibility |
| --- | --- | --- |
| Main console | `index.html`, `script.js`, `styles.CSS` | Score entry, match lifecycle, timers, lineups, rotations, audio, and popup windows |
| Volleyball rules | `matchRules.js` | Pure scoring, serve-order, overlap, and libero helpers |
| Fan scoreboard | Generated by `openScoreboardWindow()` in `script.js` | Auxiliary read-only display and timeout/card/audio overlays |
| Register | `register.html` | Printable team register and position reference |
| Referee view | `referee.html`, `referee.js`, `referee.css` | Read-only mobile/tablet view, refreshed every 1.2 seconds |
| OBS bridge | `obsClient.js` | Optional local OBS WebSocket output |
| Assets | `images/`, `audio/` | Club/team logos, service marker, and sound effects |

## Live-share flow

1. The scorer selects `Second Referee QR`.
2. `script.js` posts the complete browser match state to the `live-match` Edge Function.
3. The function creates a `live_matches` row with hashed staff and referee tokens.
4. The scorer keeps the staff token only in local storage; the QR URL contains only the referee token.
5. The referee page polls the function with the referee token and receives a read-only state snapshot.
6. Local match saves debounce a staff-authorized update to Supabase.

## Services

- **Netlify:** static hosting and response headers.
- **Supabase project `IVI Volleyball Live`:** PostgreSQL table and `live-match` Edge Function.
- **OBS (optional):** local WebSocket integration; it is intentionally not configured in hosted builds.

## Technical Decisions

- No frontend framework or build tool: the operational console must run from simple static hosting.
- Pure volleyball helpers are separated in `matchRules.js` to make rule changes testable.
- Direct browser access to `live_matches` is denied by RLS. The Edge Function owns token validation and database access.
- The referee view polls instead of editing or subscribing directly to the database. This gives a simple read-only boundary and recovers from missed updates.
